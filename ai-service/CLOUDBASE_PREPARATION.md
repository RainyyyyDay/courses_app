# AI 基础审查与 CloudBase HTTP 云函数准备清单

核对日期：2026-10-18。你负责 AI 与云函数/网站对接，组员负责复习模式设计。本轮不依赖最终业务规则；只调整 ai-service，不读取 `.env`、不调用真实付费接口、不创建云资源、不部署、不启用用户自带 Key、不移除生产保护。

## 1. 已有能力及本轮结论

已复用 `GET /health`、`POST /api/ai/classify`、mock/DeepSeek、JSON Output、配置白名单、输入/结果校验、超时取消、上游错误脱敏和单进程窗口限流。项目负责人反馈本机 mock 与真实 DeepSeek 已联调通过；本轮不重做真实请求，云端验证另行完成。

| 审查对象 | 结论与本轮处理 |
| --- | --- |
| Provider | 固定官方 HTTPS 地址、不跟随重定向、max_tokens=512、上游正文最多 65536 字节，无自动重试。已有边界合理，未替换已通过联调的 DeepSeek 请求协议；新增显式 Provider 工厂，未知值拒绝 |
| 请求校验 | 五个可选字符串、每字段最多 4000 个 UTF-16 单元、总 JSON 16kb、未知字段拒绝；三项证据非空才调用。规则保留，移入独立任务合同以免未来不同业务共用错误门槛 |
| 结果校验 | 只输出配置内 review_method、非空且最长 500 的 reason、固定 true 的 needs_review；结构不合格兜底，非法 JSON/截断报上游错误。保持合同兼容 |
| 超时与释放 | 现有 AbortController 取消有效；新增实际未结束调用计数。超时不等同上游已结束，不提前释放并发容量；补断连/异常/超时测试 |
| 错误处理 | 原有 JSON 错误与上游状态映射保留，新增 503 AI_BUSY；不透传异常/上游正文。AI_BUSY 不代表上游限流，也不会改用 mock |
| 日志 | 原本没有请求内容日志；新增默认关闭、仅白名单元数据的诊断与服务端 X-Request-ID。测试涵盖题目、查询参数、Authorization、伪造请求 ID 和异常内容不会进入日志；不等同于已经上线监控 |
| 限流/费用 | 原 60 秒 30 次窗口计数继续工作；新增默认同时两次 Provider 调用，直接拒绝超限请求、不排队。单实例计数仍不是费用硬上限 |

普通自动测试共 18 组，含 7 组新覆盖；真实集成测试仍独立，普通测试不加载 `.env`。本轮验证无 Key 的集成测试会跳过。它们不能替代云环境连通、认证、网关和费用验收。

额外运行原项目 `npm test --prefix back` 未通过：最终报临时目录清理 EPERM。只读核对发现该测试断言数据库版本 12，而本机数据库版本为 15，存在独立的基线不一致，清理异常可能遮蔽前面的失败；本轮不修改原测试/数据库，不宣称完整业务回归通过。课程、错题和排期相关代码没有改动。

## 2. HTTP 云函数可行性：框架兼容，当前安全边界尚不兼容

CloudBase 官方 [Express 指南](https://docs.cloudbase.net/cloud-function/frameworks-examples/express)明确支持 Express HTTP 云函数，要求服务监听 9000 端口；不需要为了使用 HTTP 云函数将现有路由改写成事件型 handler。现有 createApp 与 server 入口分离可复用，但不能原样上线。

官方 [启动文件说明](https://docs.cloudbase.net/cloud-function/develop/scf-bootstrap)要求 `scf_bootstrap`、可执行权限、LF 换行与解释器绝对路径，监听需使用 0.0.0.0；当前仓库没有该可执行部署入口，且当前代码明确拒绝公网监听。以下准备事项不改变现有保护。

官方 [运行环境支持](https://docs.cloudbase.net/cloud-function/runtime-support)列出了 Node.js 24.11 及 `/var/lang/node24/bin/node`。本模块要求 Node >=24，可按该版本做候选兼容验证；目标环境控制台可选版本、区域可用性和 CLI 运行时标识仍需实际确认，不能套用旧 Express 示例中的 Node 18。确认时也要验证当前启动参数、原生 fetch、AbortSignal 等能力。

| 平台需求 / 准备项 | 当前差异 | 后续处理与验收 |
| --- | --- | --- |
| 9000、0.0.0.0 HTTP 服务 | PORT 可配为 9000，但 HOST 只允许回环且固定回环监听 | 先完成正式认证/授权设计，再独立实现经评审的云端入口；本轮不添加公网运行开关 |
| scf_bootstrap 与工作目录 | 无 bootstrap；本地入口 src/server.js，会加载本地 .env 的是 npm start 的 Node 参数 | 将来在包根添加 LF 可执行脚本，以确认的绝对 Node 路径启动；代码路径与工作目录需确认；只用受控环境注入秘密，不打包 .env |
| 生产运行配置 | NODE_ENV=production 当前会失败 | 这是有意的上线阻断；不能用 development 冒充生产，也不能只删除校验，需安全改造及独立测试后再评审 |
| 网关来源与代理 | Origin、X-Forwarded-For、非本机 Host/远端被拒绝，trust proxy=false | 查明实际转发头和代理链；区分来源校验与用户认证，不能信任客户端伪造身份或删除上下文来放行 |
| 路由与网站地址 | 无云域名、路由映射和网站 AI 配置 | 确认外部路径及前缀剥离；原课程 API 保留，新增独立 AI_API_BASE；方案见 API_CONTRACT 第 11 节 |
| 认证与业务权限 | 仅有 authenticate 中间件接入点，默认无身份验证 | 实现用户短期令牌验证、授权和防绕过；health 不检查 Key，可用于存活探针，但不等同上游 readiness |
| 请求/响应透传 | 服务有 16kb、AI 超时、JSON 错误和来源头 | 网关与运行时超时应给 AI 超时及返回错误留余量；确认大小限制、403/429/5xx、来源头、X-Request-ID、Retry-After 的透传 |
| 浏览器认证调用 | 无 CORS/OPTIONS 允许策略，当前拒绝 Origin | 明确同源代理或受限跨域入口；按选定方案实现来源、Authorization 允许及响应头暴露、CSRF/凭证策略 |
| 网络与模型 | 仅出站 api.deepseek.com:443；本机成功不证明云端成功 | 验证 DNS/TLS 出站、目标账户模型可用性和秘密注入；用固定虚构题做一次最小云端验收，不记录正文 |
| 多实例和成本 | 每实例各自限流及并发计数，实例重启重置 | 设置实例/平台并发预算；实现共享按用户配额、费用预算和告警，避免平台自动重试扩大成本 |

## 4. 正式上线仍缺少的安全措施

| 缺口 | 下一步需要落实 |
| --- | --- |
| 身份认证 | 选择用户身份系统；验证真实签名/有效期/签发者/受众（按所选体系）、退出/刷新及撤销；统一 401 响应。不能把上游 AI_AUTH_FAILED 当作学生未登录 |
| 权限控制 | 验证用户与课程/资源归属；限制调用用途和角色；身份来自受信任验证上下文，不能只信请求体用户 ID |
| 费用硬限制 | 共享按用户和全局用量计数、并发/每日预算、预算前置预留与结算、超预算拒绝、账户余额和账单告警；当前 max_tokens、速率/并发只是辅助约束，无法保证某个金额上限 |
| 秘密治理 | 服务端安全注入、最小权限、轮换/撤销、访问审计；不开启用户自带 Key；平台和网关日志也必须脱敏 |
| 集中监控 | 汇聚请求 ID/错误比例/P95/P99 时延/429/503 AI_BUSY/504/兜底比例/费用及 Token 用量；本轮无 Token 统计、云指标、告警或值班渠道 |
| 隐私与输出 | 文字发到外部 Provider 的知情与数据最小化、保留/删除政策；输入不自动脱敏；输出语义和提示注入防护还需评估，界面使用 textContent |
| 发布和应急 | 依赖/配置审查、灰度/回滚、泄漏撤销、超预算停用方案和演练；健康检查应与上游连通性区分 |

`AI_LOG_REQUESTS=true` 时只输出固定事件元数据，可用于本机排障；默认 false。X-Request-ID 为服务器随机 UUID，不接受客户端值，不记录原始 URL、请求头、用户内容、模型结果或异常。外部日志系统的保留和访问权限尚未配置，不应将本轮诊断称为完整可观测平台。

## 5. 不依赖最终设计的扩展边界

- 输入 `error_type`：由调用方明确提供的错误原因标签；本轮没有新增错误原因推断。
- 输出 `review_method`：配置中的临时复习方式标签，不代表已经实现该复习流程。recall/guided/retry 的含义及映射仍为示例，不在本轮定稿。
- 输出 `needs_review=true`：固定人工复核标志，不是判对错、学习进度或掌握度。
- 原错题业务另有 `mistakeType`（请求）/`mistake_type`（存储），取值 knowledge/thinking/execution/unclassified，见 back/db/mistakes.js 与 fronted/js/mistakes.js；还有独立 review_status。它们不是本服务的 error_type、review_method 或 needs_review，没有自动映射或回写。尤其 knowledge 不等同示例 knowledge_gap；不能未经业务确认直接复制枚举。现有 AI 接口仍拒绝 mistakeType/mistake_type 等未知字段，测试已覆盖。
- `src/contracts/classification.js` 仅定义当前分类的输入、证据门槛和输出白名单；未来笔记/资料推荐、挖空和答案评价要分别建合同及路由/测试，不复用错题的强制 error_type 门槛。
- `src/providers/index.js` 明确选择 Provider；未来百炼可在此与配置白名单中注册。现有 classify 能力不应伪装成通用 generate/evaluate 功能，新的 Provider 能力签名要在业务需求确认后定义。
- 后续路由可复用认证接入、速率/并发防护、超时取消、诊断和错误封装，但必须确认每种任务的输入/输出、费用上限和人工兜底。当前没有自动路由注册或泛化业务字段。

业务讨论材料及候选接口见 [API_CONTRACT.md](API_CONTRACT.md) 第 9 节。待你与组员共同确认：正式模式/类别与代码、error_type 的来源和证据、各资源最低信息、自动推荐与人工选择关系、挖空答案可见性、多解/评分与“无法判断”、结果保存与复习排期的整合边界。未确定前只保留示例类别和现有契约。

还需明确原错题类型与 AI 错误标签是否保留为两个概念、由谁维护映射、是否允许人工修改及何时失效；本轮没有变更原类型或原复习流程。
