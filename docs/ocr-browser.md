# 浏览器端 OCR

2026-10-24：一键启动的主入口为 `http://127.0.0.1:3000/`。图片 OCR、PDF 文字提取和 Word/PPT 文字提取均可在浏览器中完成；Python AI 服务为可选服务，不参与文档文字提取。

错题上传时的「识别文字」默认在**浏览器里**跑：官方 `@paddleocr/paddleocr-js` + ONNX Runtime Web + PP-OCRv5 mobile 模型。图片不上传、不需要服务器算力。

## 为什么要改打开方式

浏览器端 OCR 依赖 10MB 的 JS 脚本、13–27MB 的 wasm 运行时和模型 tar。`file://` 协议下这些全被浏览器拦掉，所以页面必须通过 http 访问：

```
http://127.0.0.1:3000/
```

后端已经顺带托管了 `fronted/`，不用额外起服务。请不要双击 HTML 使用识别功能。图片在浏览器不可用时可以回退到 `/api/ocr`；PDF 和 Word/PPT 的失败、取消不会自动上传到服务端。

## 准备运行时资源（一次性）

产物 71MB，不入库，拉下代码后跑一次：

```powershell
cd ocr-trial
npm install
cd ..
node tools/prepare-ocr-web.cjs
```

会生成 `fronted/vendor/ocr/`：打包后的 SDK、ONNX Runtime 的 wasm、两个模型 tar。

## 运行链路

1. 用户点「识别文字」→ 前端懒加载 `fronted/js/ocrBrowser.js`。
2. 首次加载引擎（约 10MB）+ 初始化模型（约 20MB），实测冷启动 8–9 秒。
3. 之后的识别约 1 秒/张（1280×960 以内）。
4. 图片识别在浏览器不可用时回退到服务端 `/api/ocr`；PDF 和 Word/PPT 保留用户选择的范围，失败时不自动回退。

## PDF

PDF 支持全部页面或指定页码（例如 `1-5, 8`），不再限制前 10 页。有文字层的页面直接提取文字，无文字层的扫描页再渲染并 OCR。

- 逐页处理、显示进度，及时释放画布。
- 支持取消：不再启动下一页；当前 OCR 推理需等本页结束。
- 取消或失败保留原正文和已有结果，不自动上传到服务端。
- 结果保留页码和空白页提示，纯文字提取不显示 OCR 置信度。

详见 [附件预览与 PDF 识别](attachment-preview.md)。

## 智能合并段落（2026-10-26）

图片和扫描 PDF 默认在识别后保守合并段内折行。使用原始文字框的行距、字高、缩进及正文右边界判断连续关系；不修改识别出的文字。英文单词之间补空格，中文连续拼接。

- 新题号、选项、标题、答案/解析标签、明显段落间隔和缩进保留换行；较长题目或选项自身的续行可合并。
- 句末完整标点、公式特征、缺失/异常坐标、疑似表格或双栏时优先保留原换行。不跨页合并，也不重新排序文字框。
- 有文字层的 PDF、Word/PPT 和纯文本继续保留直接提取的排版。PDF 的扫描页按页单独合并，页码标题及所选范围保留。
- 校对区可切换“智能合并段落 / 保留原始换行”。两种模式分别保存本轮手工修改；清空、更换附件或重新识别后重置。切换不直接修改已保存正文。
- 覆盖错题新建/编辑的题干与答案、资料/笔记录入及已有附件补正文、考核附件、考核图表附件提取、创建时 AI 复习建议的附件读取，以及 OCR 自检和对比试验页。
- 服务端回退保留文字框坐标和页码，返回前端后使用同一合并规则；模型无需调整。直接调用服务端接口仍返回逐行原文。

实际截图复核修正：同一行被拆成标题和括号后缀时，只在附近判断分栏冲突，不能因此跳过整页合并；正文右边界按附近同字号、同栏文字估计。允许项目符号后的悬挂缩进，并保护“第…场/章/节/题”等新条目。截图正文区域实测从 20 行还原为 12 行（6 处段内折行、2 处同排标题后缀），识别字符保持一致。新增对应布局回归后，OCR 专项 16/16 通过。已保存正文需重新识别并明确替换保存，不自动迁移旧内容。

### 圆点整理试验（默认关闭）

打开 `http://127.0.0.1:3000/ocr-bullet-trial.html`，选择图片或 PDF，点击“识别并对比”，可并排查看原始识别、合并段落和统一列表圆点。此页面仅预览，不调用业务保存接口。正式 OCR 校对区也新增“试验：统一列表圆点”，需主动选择；各模式分别保留草稿。

试验把明确的行首 `●`、`•` 等列表符号统一为 `• `。仅在至少三条顺序连续的“第…场/节/章/题/幕”条目中已有圆点依据时，尝试补齐漏识别项；没有圆点依据、跨空行、跨页、编号不连续时不推断。正文间隔点、数学符号、问号、000、页码及工具栏文字不删除。该试验会修改列表符号，原始识别和默认段落合并模式仍保留原字符。

截图正文真实识别对比中，已统一不同大小的圆点，并补齐同一组八个条目中第五、第七条漏识别的圆点。OCR 专项新增试验和草稿切换回归后为 17/17 通过；这不是通用准确率评估。

验证：`node --test tests/ocr-paragraphs.cjs tests/pdf-ocr-pages.cjs tests/mistake-ocr-options.cjs tests/ocr-web-smoke.cjs`。覆盖中英文折行、结构保护、跨页、真实浏览器切换和手工草稿、真实本地 OCR 模型识别合成长中文图片；合并前后识别字符一致。桌面和手机尺寸的相关资料、笔记、考核、已有附件及 AI 复习建议测试亦已运行。

相关 OCR 验证通过，但扩大回归时有四项已有失败：错题复习状态/API、旧错题迁移、复习计划迁移、复习会话迁移（状态预期不一致或缺少 outline 列）。已用临时目录中的未修改 HEAD 复现相同四项失败。本次不调整这些无关逻辑。尚未用用户真实图片集统计误合并率和漏合并率，不能据合成样例宣称固定准确率。

## Word 和 PPT

支持 `.docx` / `.pptx` 的本地文字提取，不启动 OCR 引擎或 AI。PPT 可选择全部页面或指定页码；旧版 `.doc` / `.ppt` 提示另存为新格式。依赖准备、范围和验证说明见 [Word/PPT 文字提取](office-text.md)。

## 实测（同一张 980×366 小字题图）

| 路径 | 冷启动 | 热识别 | 准确度 |
| --- | --- | --- | --- |
| 浏览器端（PP-OCRv5 mobile） | 8.8s | 1.07s | 文字正确，全角括号会变半角、空格丢失 |
| 服务端（PP-OCRv6 medium） | — | 约 12s | 全对 |

浏览器端快十倍，但模型小一档：标点和个别形近字会错（实测「眼睛」→「眼晴」）。所以校对面板必须保留，不能直接入库。
