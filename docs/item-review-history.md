# 条目复习历史与 AI 批改保存（2026-10-22）

## 正常网站操作

资料、笔记、错题的普通“查看”详情页底部都有折叠的“复习历史”。展开后每页20轮，按时间倒序；摘要显示实际执行模式、完成情况、原评分及批改版本数。点开一轮才加载题面、参考、首次作答、耗时和批改全文。查看、翻页和刷新不调用模型，不改变评分或排期。

原复习页的“AI 批改与错误解析”依旧完全可选。用户主动请求并获得有效结果后自动保存，显示“批改已保存到本轮历史 · 版本 N”；同一轮再次获取生成新版本，不产生新复习轮次，也不覆盖旧解析。Mock 明确保留来源标签，不冒充实际批改。重新打开已作答轮次时，可直接恢复已保存的最新版本，不需要再次花费请求。

批改保存失败时保留页面内结果，并提供“重试保存（不调用 AI）”。使用同一个请求编号重试，不重复记版本；未保存前提示不要离开页面，也不允许用新模型请求覆盖待保存结果。失败的模型请求不产生批改版本。清除临时 Key 不删除已保存的历史。

## 复用与边界

- 材料工作台：直接查询 `review_mode_attempts` 的不可变题面快照、首次作答、状态和原评分，不另复制轮次。
- 原错题步骤机：按已有事件中的题目版本＋round 分组，一轮只显示一次；读取该轮事件响应中的历史文字，而不是现在的题目。新增评分证据仅附加轮次关联键，不改评分公式。旧轮次没有评分关联时明确说明，不猜分、不补造记录。
- 原资料／笔记阅读：实际打开已有会话项目时保存一次正文快照，刷新同一项目不新增轮次。完成情况复用会话项目，阅读仍只计曝光，不产生 Good。没有打开的候选项目不伪造历史；切换到材料任务后不重复展示原阅读占位。
- 历史中未完成、已作答待自评、已完成、已跳过分开展示；未揭示答案的轮次不能通过历史接口提前查看答案。
- 老阅读记录未留当时正文时只显示已有曝光记录并注明缺快照，不把当前正文冒充过去的材料。
- 过去仅存在页面内存且已丢失的 AI 批改无法补回。本功能启用后的成功批改才会持久保存。

## 数据与接口

数据库整合后统一使用 v24：保留组员 v22→v23 的导图图片迁移，v23→v24 按缺项补齐导图图片字段、`review_ai_feedback`、`review_reading_history` 及查询索引，兼容此前两种不同的 v23 数据库；不重建或清空旧表、旧图片或批改记录。AI 接口仍是 Python JSON 入出，不直接写库；网站通过已有业务后端单独保存结果。无需新增依赖。

统一前缀：`/api/courses/:courseId/review-items/:itemType/:itemId/history`。

- GET：分页摘要，`before` 为服务端返回的游标。
- GET `/:historyKey`：轮次详情及最新10份批改版本；`beforeFeedbackId` 查询更早版本。
- POST `/:historyKey/feedback`：仅接受 `{requestId,provider,model,feedback}`，不接受 Key、题面替换、分数或任意字段。服务端验证轮次归属、作答状态、引用确实出自本轮作答及结构／长度。响应 `{saved:true,id,version}`；同编号同内容幂等，不同内容409。
- POST `/reading`：仅接受已有且属于本条目的 `sessionItemId`，保存正文快照，不创建评分。

轮次键：`w:attemptId` 为材料任务，`n:reviewRevision:round` 为原错题，`r:sessionItemId` 为原文阅读。所有读写校验课程、条目类型和 ID；接口 `Cache-Control: no-store`。不保存 API Key、完整网络响应或上传附件副本。文件仅引用原有地址，原文件被删除后不能保证查看原附件。

当前为项目现有本地 Node/SQLite 业务后端；没有新增账户系统。将来主后端整合时仍需要宿主按登录用户校验课程所有权，不能把本地的 ID 归属检查当作生产鉴权。

## 测试与启用

测试 `tests/item-review-history.cjs` 覆盖 v22、仅历史表的 v23、仅导图图片的 v23→v24 增量迁移与 v24 重启幂等、旧记录保护、三个类型、未提交答案防泄露、快照、真实原评分、幂等／版本冲突、越界内容、历史及版本分页、阅读曝光，真实 Chrome 桌面／手机刷新查看，不请求模型。

`tests/review-feedback.cjs` 经 Python 假上游验证主动请求后保存、保存失败单独重试、恢复已保存批改不再次请求模型以及原客观评分保护。真实 DeepSeek 的准确性、延迟与费用仍未做在线验收。

启用时需要重启业务后端3000，让它执行增量迁移，再刷新3002页面。已有3002 Python服务无需为这项新增独立模块；AI仍走原批改接口。代码测试只使用临时虚构数据库，未启动或迁移用户实际数据库，未读取 `.env` 或调用真实模型。
