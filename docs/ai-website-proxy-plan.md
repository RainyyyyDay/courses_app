# 网站后端 AI 转发：当前状态与下一步

核对日期：2026-10-18。

## 当前实现

- 浏览器端预留 `classifyMistakeWithAi(input)`，固定调用现有 `${API}/ai/classify`；不接触 CloudBase 地址或任何密钥。
- 网站后端挂载同一路径，但默认返回 `503 {"error":"AI_AUTH_NOT_CONFIGURED"}`，且不会发起网络请求。
- 转发模块要求认证适配器附加服务端已验证的 `req.user.id`，只接受现有五个文字字段、固定拼接 `/api/ai/classify`、只接受服务端配置的 HTTPS 基址，并限制响应大小、超时和响应字段。
- mock 测试只使用内存假上游与 `.invalid` 演示域名；不读取 `.env`、不访问 SQLite、不调用真实 AI。

这不是已经完成的线上认证或 CloudBase 部署。现有网站没有登录身份，因而不能安全开启转发；静态共享密钥、检查某个 Header 是否存在、依赖 CORS 或仅做 IP 限制都不能替代用户认证。

## 开启转发前必须补齐

1. 选定网站登录方案，并让后端验证短期用户凭证的签名、签发者、受众和有效期。
2. 将验证后的用户身份传入 `createAiProxy({ authenticate, ... })`；禁止信任客户端提交的 `user_id`。
3. 在网站后端配置固定 CloudBase HTTPS 基址，并为网站后端到 CloudBase 配置独立、可轮换的服务身份；当前模块尚未实现该服务身份头。
4. CloudBase 侧验证服务身份，并实现跨实例的按用户额度、总预算和并发限制。
5. 完成生产 HTTPS、同源部署或严格来源/CSRF 策略、脱敏审计、隐私告知和失败监控。

## 下一步单一操作

确定网站登录/身份方案，并写出一份可验证的令牌合同（签发方、受众、有效期、后端验证库、用户 ID 来源）。在该决定完成前，保持当前 AI 路由关闭。
