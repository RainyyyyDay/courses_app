## OCR：已准备的是哪一条路径

本机 `fronted/vendor/ocr` 已有官方浏览器 SDK、两个模型 tar、ORT WASM/MJS 和 PDF.js（共九个必要文件）。浏览器 OCR 不依赖 Python。此前启动脚本只检查 8001 的 Python PaddleOCR，缺包时错误暗示“整个 OCR 不可用”。本机 Python 3.14 的隔离/非隔离元数据探测均缺 PaddleOCR 等服务端包，不能声称服务端环境已经恢复。

`start-local.ps1` 现在分别检查浏览器资源及服务端健康。浏览器资源齐全时不强制探测/启动缺依赖的备用服务，说明“资源已准备、运行时初始化待识别时检查”；8001 不可用只表示备用识别缺失。资源不完整时保留原服务端探测/启动；两条路径都失败也不阻塞网站，不切 Mock。`ocr-service/start.ps1` 的失败提示明确只指服务端备用路径；原 .venv → py -3 → PATH 选择顺序不变，没有安装或下载。

验证不仅检查文件：`tests/ocr-web-smoke.cjs` 启动独立静态测试页，在 Chrome 内用本地 WASM/模型实际识别测试生成的“Math 1 + 1 = 2”图片，断言真实读取了 WASM/tar，阻止外网与 8001；通过。未使用用户附件。脚本测试另验证齐全资源跳过 Python 探测、删去一份模型的测试副本后回到原预检分支。

## 资料／笔记的完整路径

原资料／笔记详情页和复习页新增折叠的“AI 复习建议”，仍用原页面：

1. 选择已校对正文片段、学习目标；当前回忆/困难可选。不要求错因/学生错误答案，不借用错题诊断。文件无正文时需手动提供文字片段；超过4000字需自行选片段，不静默截断或上传附件。
2. 默认可用 Mock 规则演示；真实调用读取右下角统一设置及临时 Key，失败不回退 Mock。生成结果仅预览，不覆盖原手选项。
3. 明确确认才将模式 ID 保存到 `resource-ai-method:<courseId>:<material|note>:<id>`，不同类型/课程隔离，只存模式，不存 Key、正文或分析。可不用 AI，直接手选确认。
4. “准备所选模式材料”复用原编辑器；复习中工作台仍内嵌原复习页面。已确认建议进入总复习/考前计划的原模式选择路径，用户本次选择优先，其次已确认建议，最后规则推荐。不悄悄修改进度/评分/计划。
5. 缺材料明确说明缺项，提供手动准备和回到原阅读。建议不是材料，材料仍需单独确认保存。自述、挖空、对比、标准、阅读均复用原工作台/引擎；retry 重开已有任务，无任务先手动准备；阅读走原阅读或工作台曝光，不自动 Good。
6. 有建议时可一键切回原阅读、再切回 AI 建议；无建议时原阅读/设置入口保持原样。新建议不会重写当前显式选择或已运行轮次。共享权限/凭据仍由统一设置及原后端依赖约束。

新增 `fronted/js/resourceAi.js`、Python `src/ai_review_suggestion.py`（导出 `register(app, dependencies=...)`，默认拒绝无鉴权注册），路由 `POST /api/ai/review-suggestion`。收发 JSON，不访问 DB。复用已有官方 DeepSeek 传输、限流并发/取消基础；Mock 有明确标识。新模块已注册到本地 `test_app.py`，没有主后端部署改动或新依赖。

## 浏览器验证步骤

1. 正常停止旧 Node 和 FastAPI 窗口（Ctrl+C），重新运行 `start-local.ps1`，打开 `http://127.0.0.1:3002/` 并 Ctrl+F5。不要终止不明进程；脚本仍不会抢占已有端口。刷新会清除标签页内 Key，需真实 AI 时重新应用设置。
2. 上传错题附件，点“识别文字”，应显示浏览器引擎/模型进度和浏览器识别结果，仍需校对。8001 备用未启动不影响已就绪浏览器路径；不同设备/浏览器兼容性仍以现场结果为准。
3. 打开资料详情或笔记详情，展开 AI 复习建议，提供一段文字并选择“理解讲清”等目标，获取建议，再确认。可先使用 Mock；其结果仅为规则演示。
4. 准备并明确保存对应模式材料，从原总复习/计划进入，核对当前实际模式和页面输入控件。点快捷切换可回原阅读再切回，原输入/评分规则保留。
5. 对已有结构化选项的错题选“重新作答”，确认后应出现原 radio/checkbox，而不是普通文本框；旧历史不被覆盖。
