# 大纲润色 / 思维导图生成的 AI 契约

## 为什么必须先润色

用户写的大纲是自由文本，可能是：

- `第一章 函数\n1.1 极限\n1.2 连续`
- `函数：极限、连续、导数`
- `极限很重要，连续次之，导数最难`
- 整段没有分行的笔记

靠规则只能猜层级，用户写法一变就分不清父子关系。所以**层级判断交给模型**，规则只做兜底。

## 接口

```http
POST /api/ai/outline
Content-Type: application/json

{
  "title": "高等数学 · 第一章",
  "text": "用户的原文（大纲 / 重点总结 / OCR 出来的正文）"
}
```

返回（严格 JSON，不要 Markdown 代码块）：

```json
{
  "title": "高等数学 · 第一章",
  "nodes": [
    {
      "text": "函数",
      "children": [
        { "text": "极限", "children": [] },
        { "text": "连续", "children": [] }
      ]
    }
  ]
}
```

## 硬约束（写进提示词，后端也要校验）

- 最多 3 层；单个节点文字 ≤ 20 字；总节点 ≤ 60
- 只做归纳，**不得添加原文没有的知识点**
- 保留原术语（如「洛必达法则」不要改成「求导规则」）
- 同级节点粒度一致（都是章节，或都是要点）
- 只用纯文本，不带 Markdown、编号prefix、LaTeX
- 输出必须是可 `JSON.parse` 的对象

## 提示词（可直接交给负责 AI 的组员）

```
你是学习资料的整理助手。用户会给你一段学习材料原文，请把它整理成思维导图层级。

要求：
1. 只使用原文出现的内容，不要补充新知识。
2. 输出严格 JSON：{"title": string, "nodes": [{"text": string, "children": [...]}]}
3. 最多 3 层；每个节点不超过 20 个字；总节点不超过 60 个。
4. 同级节点粒度必须一致。
5. 不要编号、不要 Markdown、不要解释，只输出 JSON。

标题：{{title}}
原文：
{{text}}
```

## 异常与兜底

| 情况 | 处理 |
| --- | --- |
| 模型返回带 ```json 围栏 | 后端剥掉围栏再解析 |
| JSON 解析失败 | 重试一次；仍失败 → 用规则解析器 |
| 节点数超限 | 按层截断并提示「已精简」 |
| 层级只剩一层 | 仍然可用，但 UI 提示「未能识别出层级」 |
| AI 未配置 / 超时 | 规则解析器 + 提示「粗略分层，可手动调整」 |

## 当前实现：基础生成与 AI 润色分开

- `POST /api/ai/outline` 保持无模型依赖。正文提炼仍返回 `{ outline }`；请求带
  `{ purpose: "mindmap" }` 时，由服务端固定规则把已有大纲切成最多 3 层、60 个节点的
  `- ` 纯文本层级，并返回 `{ outline, mode: "basic" }`。
- `POST /api/ai/outline-polish` 只接受真实 API 凭据，返回严格结构
  `{ provider, result: { title, outline, needs_review: true } }`。`outline` 同样采用
  `- ` 纯文本与每级两个空格缩进的格式，并要求“不新增原文没有的知识点”。
- 前端「基础生成」始终可用；「AI 润色生成」只在共用 AI 设置中存在真实 Provider 和
  Key 时解锁。Mock、未配置或 Key 已清除时按钮禁用，基础规则仍可独立完成生成。
- AI 结果先进入可编辑大纲和导图草稿，不自动覆盖已保存内容。详情页把选中的生成结果
  作为一次性 `outline` 交给导图交接接口，只有用户在导图工具里保存并回传后，
  `mindmap_json` 才会更新；`outline` 原字段不会被自动改写。

## 固定规则能做什么

能识别并转换：`第X章`、`一、`、`（一）`、`1.` / `1.1`、`#`、缩进、列表符号；
无显式结构时还会按分号、句末标点以及“主题：并列项、并列项”做保守切分。
规则不会补全原文没有的内容，也不尝试推断深层因果；语义层级与长句润色交给可选的 AI。
