# 大纲润色 / 思维导图生成的 AI 契约

## 为什么必须先润色

用户写的大纲是自由文本，可能是：

- `第一章 函数\n1.1 极限\n1.2 连续`
- `函数：极限、连续、导数`
- `极限很重要，连续次之，导数最难`
- 整段没有分行的笔记

靠规则只能猜层级，用户写法一变就分不清父子关系。所以**层级判断交给模型**，规则只做兜底。

## 接口

```http
POST /api/ai/outline
Content-Type: application/json

{
  "title": "高等数学 · 第一章",
  "text": "用户的原文（大纲 / 重点总结 / OCR 出来的正文）"
}
```

返回（严格 JSON，不要 Markdown 代码块）：

```json
{
  "title": "高等数学 · 第一章",
  "nodes": [
    {
      "text": "函数",
      "children": [
        { "text": "极限", "children": [] },
        { "text": "连续", "children": [] }
      ]
    }
  ]
}
```

## 硬约束（写进提示词，后端也要校验）

- 最多 3 层；单个节点文字 ≤ 20 字；总节点 ≤ 60
- 只做归纳，**不得添加原文没有的知识点**
- 保留原术语（如「洛必达法则」不要改成「求导规则」）
- 同级节点粒度一致（都是章节，或都是要点）
- 只用纯文本，不带 Markdown、编号prefix、LaTeX
- 输出必须是可 `JSON.parse` 的对象

## 提示词（可直接交给负责 AI 的组员）

```
你是学习资料的整理助手。用户会给你一段学习材料原文，请把它整理成思维导图层级。

要求：
1. 只使用原文出现的内容，不要补充新知识。
2. 输出严格 JSON：{"title": string, "nodes": [{"text": string, "children": [...]}]}
3. 最多 3 层；每个节点不超过 20 个字；总节点不超过 60 个。
4. 同级节点粒度必须一致。
5. 不要编号、不要 Markdown、不要解释，只输出 JSON。

标题：{{title}}
原文：
{{text}}
```

## 异常与兜底

| 情况 | 处理 |
| --- | --- |
| 模型返回带 ```json 围栏 | 后端剥掉围栏再解析 |
| JSON 解析失败 | 重试一次；仍失败 → 用规则解析器 |
| 节点数超限 | 按层截断并提示「已精简」 |
| 层级只剩一层 | 仍然可用，但 UI 提示「未能识别出层级」 |
| AI 未配置 / 超时 | 规则解析器 + 提示「粗略分层，可手动调整」 |

## 我们这边已经就位的部分

- `POST /api/ai/outline` 这个接口已经存在，目前用本地规则实现
- 前端已经有「自动生成」按钮、大纲编辑框、`outlineToMindmap()` 转换器
- 导图数据落到 `mindmap_json`，原文留在 `outline`

**负责 AI 的组员只需要把 `/api/ai/outline` 的实现换成调用模型**，返回上述 JSON，前端一行不用改。

## 规则兜底现状（供对比）

现在能识别：`第X章`、`一、`、`（一）`、`1.1`、`#`、缩进、列表符号。
识别不了：语义层级（"极限很重要，连续次之"）、并列关系、无标点的整段文字。
