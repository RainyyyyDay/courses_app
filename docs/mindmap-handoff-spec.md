# 导图工具 ↔ 课程网站 交接说明（给导图作者）

## 目标

课程网站不嵌画布，只做三件事：**跳转过去 → 带过去预填数据 → 收回来展示**。

## 我们这边已经做的

- 详情页右上角按钮「在导图中新建」，打开：
  `{导图工具地址}?from=courses_app&title=<标题>&outline=<大纲>`（URL 编码）
- 用户在你那边导出/回传后，我们上传弹窗可以导入 `map.json`，详情页直接浏览

## 需要你做的

### 地址来源

课程页面可能由本地 FastAPI（3002）提供，而业务 API 在后端 3000。交接 URL 中的 `bridge` 必须按课程 API 的来源解析，不能按当前页面来源解析：

- 正常本地值：`http://localhost:3000/api/mindmap-handoffs` 或 `http://127.0.0.1:3000/api/mindmap-handoffs`
- 不接受页面来源：`http://127.0.0.1:3002/api/mindmap-handoffs`

导图工具若只接受部署白名单，还需把正式课程 API 来源加入自身的交接来源配置。

### 必做：一键回传（替代"导出 PNG 再上传"）

用户不该手动导出文件再选上传，这一步体验不可接受。请在导图页加一个按钮「回传到课程网站」：

```js
// 在导图的保存/导出附近
function sendBackToCourses(map) {
  if (!window.opener) { alert('请从课程网站打开本页后再回传'); return; }
  window.opener.postMessage({ type: 'mm:send', map }, '*');
}
```

`map` 就是你们当前的导图对象（`{id,title,nodes,pos,size,edges}`）。
我们这边会监听 `mm:send` 并直接保存到对应资料，用户无需下载任何文件。

### 可选：URL 预填（配合上面的回传更完整）

#### A. 支持 URL 预填（最小改动，1 小时）

页面加载时读 `from=courses_app`：

- 自动新建一张空白导图，标题取 `title`
- 把 `outline` 作为若干节点预置（或放进一个"待整理"节点）
- 停留在这个新导图的编辑页，而不是首页

#### B. 提供「发送到课程网站」按钮

- 用户点它时，`window.opener.postMessage({type:'mm:send', map}, '*')`
- 我们这边监听并直接保存

#### C. 什么都不做

用户手动导出 JSON，再回我们这边上传。可以跑通，但体验是你描述的那种"乱七八糟"。

## 回传格式（我们现在就能吃）

```json
{
  "id": "任意字符串",
  "title": "第一章 函数",
  "nodes": [
    { "id": "n1", "text": "第一章 函数", "children": [
      { "id": "n2", "text": "1.1 极限", "children": [] }
    ]}
  ],
  "pos": {},
  "size": {},
  "edges": [],
  "v": 3
}
```

纯文本节点即可；带图片/PDF 的节点我们会丢附件。

## 验收

1. 课程网站点「在导图中新建」→ 打开你的页面，**直接是新导图的编辑页**
2. 标题和大纲已经预填
3. 编辑完导出 → 课程网站「导入导图 JSON」→ 详情页能看到
