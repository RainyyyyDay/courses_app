# 第一轮 AI 学习分析：人工质量验收

## 自动化与真实质量的边界

自动测试使用虚构 Key、假上游和临时业务数据库，证明提示词、请求、结构校验、展示及复习衔接符合约定，不证明真实模型必然给出正确诊断。下面是人工质量验收清单，本轮没有执行真实调用，不记为通过。不需要登录系统、统一 Key 设置或生产数据库。

## 如何验收

1. 重启本地 3002 服务以加载新的 Python 提示词/契约，打开网站并 Ctrl+F5。仅刷新不能更新已运行的 Python 模块。
2. 用虚构题目，在原 AI 面板选择 DeepSeek 官方；每次自己填写本次 Key 并确认费用。错误原因保留“不确定”，有过程时才填写，不为获取建议猜一个标签。不要把 Key 或敏感题目贴进测试记录。
3. 核对“答案观察、参考答案核验、候选错因、补充问题、建议动作/备选、材料需求”。AI 观察也是待复核结论，不是系统客观判分。
4. 记录日期、模型、输入、输出和人工结论（可接受/需修改/失败），不记录 Key。不得因为请求成功或 JSON 合法就判质量通过。不同结果可接受，只要依据、局限和练习目标一致；不能要求所有错题固定选一个模式。
5. 请求失败不自动重试；结构不合法要拒绝或提示人工选择，不悄悄回退为 Mock 的“分析”。确认建议后只保存模式；分类、评分、计划不能自动改变。后续正式材料仍须另行准备和确认。

## 六组固定题目

| 场景 | 输入 | 人工验收重点 |
| --- | --- | --- |
| 无过程的加法错误 | 题目 1+1=?；学生1；参考2；原因不确定 | 可指出答案差异，不能确定是知识不足还是粗心；应追问计算过程。standard/retry 是合理暂定动作；不能只因分类为 knowledge 就固定给 cloze。 |
| 过程暴露规则问题 | 题目3-1=?；学生-2；参考2；过程“交换成1-3算得-2” | 可提出可能混用了交换规则，并引用过程；讲解/标准/重做等应有理由，仍非自动确诊。 |
| 明确事实提取 | 中国首都是？；学生上海；参考北京；过程“想不起首都” | 可给事实记忆的候选原因，cloze可以是合理建议，但应与事实提取目标相关，而非类别查表。 |
| 学生答案正确 | 1+1=?；学生2；参考2 | 不强行制造错误或认定粗心；练习可为可选巩固，不能自动扣分。 |
| 参考与题意不足 | 题目“说明这个方案为什么更好”；学生“因为更快”；无参考或背景 | 不把无依据的参考/对错当事实；说明缺少比较对象、条件或评价标准，并给可回答的追问和暂定动作。 |
| 参考可疑及错因冲突 | 1+1=?；学生2；参考3；用户自述知识缺漏 | 应检查参考3是否错误，不能仅服从参考或用户标签认定学生错误；说明冲突。 |

另测只填题目与学生答案、超长内容、题型未确认、恶意提示/HTML；不能泄露提示词/凭据，不能执行返回 HTML，不能未经确认创建材料或修改历史。

真实模型的准确性、稳定性、延迟/费用及不同模型对照，仍需按上表人工验收；本轮没有联网发送模型请求。统一账户/AI 设置、跨页面暂存 Key、自动调用是第二轮，不在本轮实现。
